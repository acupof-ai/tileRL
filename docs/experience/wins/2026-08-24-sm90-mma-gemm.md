# sm90 MMA gemm + fp4 dequant kernels (WGMMA) — H20, 2026-08-24

> Status: Shipped

## Context

The 27B slice's every linear went through the naive scalar FMA kernel
(1180 ms/tok decode, H20) — the only thing blocking 27B serving. Port the
SOTA tilelang gemm schedules (shared-memory tiling + pipelined K-loop +
`T.gemm`) to sm90 and fuse the e2m1fn dequant into the fp4 kernel.

## What Worked

- **`kernels_mma.py`**: `make_gemm_{nt,nn,tn}_mma` + `make_linear_fp4_mma`,
  ported from `examples/gemm/example_gemm.py` and the Hopper dequant+gemm
  example. f32 IO lowers to TF32 WGMMA on tiles >= 32 rows and mma.sync on
  smaller ones (128 threads for WGMMA, 64 for mma.sync — 128 threads cannot
  evenly partition a 16x16 tile across 4 warps). The e2m1fn dequant is fused
  into the fp4 kernel's K-loop (shared-memory nibble decode + float block
  scale, then `T.gemm(transpose_B=True)`).
- **Tail padding in the backend**: WGMMA requires block M/N %16 and the
  reduction dim %32. The CUDA path of `linear`/`linear_bwd`/`linear_fp4`
  zero-pads M/N/K to tile multiples so the kernel always sees exact tiles
  (decode M=1 pads to 16; all model N/K dims are already multiples of 32).
  e2m1fn has no zero, so padded WQ bytes (0x00 -> 0.5) are killed by the
  zero-padded Scale.
- **fp4 grid reconciled to e2m1fn**: `pack_fp4`/`unpack_fp4` switched from
  the OCP LUT (with zero) to e2m1fn (no zero, {0.5, 0.75, 1, 1.5, 2, 3, 4,
  6}) to match the kernel decode and the Hopper SOTA. `dequant_nvfp4` keeps
  the OCP grid — the NVFP4 checkpoint wire format is a separate concern.
- **24x decode speedup** on the 2-layer NVFP4 slice: 1180.19 -> 48.85 ms/tok
  (JIT-free, 8 tokens = 1 prefill + 7 decode).

## Rule

On sm90, `T.gemm` lowers to WGMMA only with shared-memory operands (global
operands are rejected), tiles must be %16 in M/N, and 128 threads (warp
group) cannot partition tiles smaller than 32 rows — use 64 threads (mma.sync)
for those. The SOTA pattern is: `T.alloc_shared` tiles + `T.Pipelined`
K-loop + `T.gemm` with a fragment accumulator. Fuse the fp4 dequant into the
K-loop (decode in shared, then gemm) — it is O(N*K) vs the gemm's O(M*N*K).

Day-1 ceilings (known, marked in code): f32 IO (bf16 IO would double WGMMA
throughput); decode M=1 pads to 16 rows (15/16 over-compute — a GEMV kernel
is the upgrade); GDN backward is torch-eager; tilelang eager JIT has no disk
cache.
