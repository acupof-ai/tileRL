# ncols=2 is a 1.50× win on the speculative verify path — V100 sm70, 2026-09-03

> Status: **measured at last, and it is a WIN, not the wash I published.** At the batch size
> serving actually uses (`max_batch=4`, depth 3 → **16 rows → the 32 rung**), `ncols=2`
> gives **42.7 vs 28.5 tok/s = 1.498×**. The earlier "0.995× wash" came from a harness that
> submitted one request, so both arms ran the 1-column kernel —
> [`errors/2026-09-03-the-spec-ncols-ab-ran-at-b1.md`](../errors/2026-09-03-the-spec-ncols-ab-ran-at-b1.md).
> No code changes: the shipped rung gate already turns this on.

## The measurement

`bench_ctx_decode.py --depth 3 --batch 4 --max-ctx 32 --tokens 64`, arms 2/1/2, threshold
committed in the script before launch (within 2% → the rung gate stands; a >2% loss → the
gate must key on real rows `M` rather than the compiled rung `Mk`).

| arm | tok/s | ms/tok | tok/fwd |
|---|---:|---:|---:|
| `TILERL_NCOLS=2` | **42.7** | 23.4 | 8.64 |
| `TILERL_NCOLS=1` | **28.5** | 35.1 | 8.64 |
| `TILERL_NCOLS=2` (confirm) | **42.8** | 23.4 | 8.64 |

**1.498×**, and the two `ncols=2` readings agree to **0.23%** — inside the noise floor, so
the arms measure the flag rather than drift. That third arm is the check the first attempt at
this A/B never had.

Against a harness noise floor of **1.16%** (one kernel measured twice across five contexts)
a 49.8% effect is **43× the floor**, so it is not a reading artefact.

**`tok/fwd` is identical to the hundredth in both arms — 8.64.** Acceptance is a property of
the draft and the trim, not of the GEMV schedule, so a flag that changed it would mean the
flag was changing more than the kernel. It didn't, which makes this a pure kernel-time
delta: same tokens, same forwards, 33% less time per token.

## Why 1.50 and not 1.82

The microbench measured `ncols=2` by rows: **M=1 1.05×, M=8 1.72×, M=32 1.82×**. A verify
tick at B=4 W=4 submits **16 real rows**, which the sm70 ladder (`1, 2, 4, 8, 32` — no rung
between 8 and 32) launches as **32**. So the kernel does M=32 work for M=16 of use, and
1.498× sitting *below* both the M=8 and M=32 microbench points is what that predicts.

The three model-level points are now monotone in real rows, which is the mechanism rather
than a coincidence:

| path | real rows | launched | end-to-end |
|---|---:|---:|---:|
| dense decode | 1 | 1 | **0.951× — a loss, gated off** |
| speculative verify | 16 | 32 | **1.498×** |
| prefill | 512 | 512 | **1.520-1.600×** |

The gate keys on the compiled rung `Mk >= 32`, which is why the verify path gets the win
without any change: 16 rows round up into the rung the gate admits.

## What the wash reading cost

The withdrawn A/B read 0.995 / 1.000 / 0.988 / 0.996 / 0.998× across five contexts and I
recorded it as "worst 1.2%, inside the threshold". The true effect is **1.498×**. A null
result was not merely uninformative, it was 50 percentage points from the truth — and the
tell was in the printed numbers, since two different kernels do not track each other to
0.5% over a 128× context sweep.

Getting the real number took four more fixes to the harness (state-pool sizing, a missing
`precapture()`, an OOM ceiling, and a six-minute hang with the GPU at 0%), all recorded in
the error entry. **The bring-up cost more than the measurement**, and every one of those
failures was silent.

## Rule

**A perf claim about a row-count-gated path must state the rows it ran.** The gate keys on
`Mk`, the compiled rung, which is set by `B·W` — and a bench that submits one request has a
different `B` from serving. "Spec decode at depth 3" named the depth and hid the batch, which
is the half that selects the kernel.

Second: **suspiciously good agreement is as informative as a suspicious difference.** 1.16%
is this harness's floor for one kernel measured twice; arms agreeing inside that are the
same binary until proven otherwise.

## Gate

No code changed — the shipped `_NCOLS_MIN_M = 32` rung gate already enables this path. 189
tests pass, ruff clean. Greedy text parity for `ncols=2` was established separately at M=1
and M>8 (`scripts/parity_ncols.py`).
