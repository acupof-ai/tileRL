# The mesh, and a control that passed because the tensor had a local term, 2026-09-05

## Context

`shard_params` and `tp_config` have shipped since 08-30, and #115/#119 made the
backward correct, but nothing chose a layout: `init_tp(world, rank)` treated the
whole world as one TP group. That is right for pure TP and wrong the moment
`dp > 1`.

## What worked

`Mesh(dp, tp, cp, rank)` in `tensor_parallel.py`, with the design's rank layout —
**cp fastest, then tp, then dp** — so a tp group is contiguous and lands inside
one node:

```
rank = ((dp_i * tp) + tp_i) * cp + cp_i
```

`cp > 1` raises. The axis is in the arithmetic because leaving it out would mean
renumbering every rank when CP lands, but no context-parallel op exists, and a
mesh that accepted `cp=2` would run tp-only math on a sequence it claims to have
split.

**`init_tp` takes every tp group, not just this rank's.** `dist.new_group` is
itself collective: every rank must call it for every group, in the same order, or
the ranks that skipped one deadlock the first time it is used. Passing only the
local group is the shape that looks right and hangs.

## The gate, and the version of it that was vacuous

Four gloo ranks as `(dp=2, tp=2)`, each dp replica on a different batch.

**First version compared dp0's and dp1's gradients** on the theory that an
ungrouped all-reduce would merge the batches and make them identical. Ran the
control — the ungrouped arm — and it **PASSED**. The gate could not fail.

Why: `embed_tokens`' gradient keeps a local scatter term over each replica's own
token ids, so dp0 and dp1 differ (max|d| 3.4e+02) even with the all-reduce
wrongly spanning all four ranks. The tensor I compared had a component that
varied for a reason unrelated to the bug.

**Fixed by asserting the collective instead of its downstream effect.** A
rank-valued probe has no local term to hide behind:

```
grouped:   {0: 1.0, 1: 1.0, 2: 5.0, 3: 5.0}   each tp group's own sum
ungrouped: {0: 6.0, 1: 6.0, 2: 6.0, 3: 6.0}   the whole world  -> control FAILS
```

Plus the end-to-end check that tp ranks within a replica agree, which is the tp
all-reduce doing its job.

`tensor_parallel.py`'s `__main__` covers the layout arithmetic without any
processes: every rank in a `(dp=2, tp=4)` world lands in exactly one tp group and
one dp group, and the two intersect in that rank alone — a layout bug that
duplicates or drops a rank fails there rather than as a hung collective.

## What this does NOT establish

Nothing *selects* a mesh yet: no CLI flag, no recipe field, and `parallel.py`'s
`DataParallelEngine` still builds its replicas independently of it. This makes a
layout expressible and correct, not reachable. No 27B run (`pending-remote`), and
world=4 on CPU is the largest exercised.

## Rule

**A control has to be sensitive to the defect, not merely downstream of it.** The
gradient was downstream of the collective, and something else contributed to the
same number, so the defect's signature was masked. When the assertion can be
placed on the operation itself — a value whose correct result is known per rank —
put it there; every layer between the bug and the assertion is somewhere the
evidence can be diluted.
